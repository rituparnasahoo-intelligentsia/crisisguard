# CrisisGuard AI - hospital-wide resource coordination (backend, Phases 1-3)

A **fictional-data prototype** of a human-supervised hospital emergency coordination flow:
an AI *proposes* resource assignments, deterministic Python *validates* them, a human
*reviews* them, and only then are changes committed to PostgreSQL.

> **Not a medical device.** Simulated data only. Not clinically validated; must not be used in
> a real hospital or with real patient or staff data. Clinical policy and ICU placement rules
> in this repo are **demo placeholders** that real deployments would need qualified clinicians to define.

## Status

| Phase | Content | State |
|---|---|---|
| 1 | Audit of the nurse-only project | Done |
| 2 | Hospital-wide entity design | Done: `docs/erd.md` |
| 3 | Migrations, Docker, fictional seed data | Done and tested (below) |
| 4+ | State retrieval, multi-resource validator and approval, AI agents, API, simulator, React | Not built yet |

The original **nurse-only workflow still works** (`validator.py`, `approval.py`, all original
tests). It will be replaced by the bundle workflow in later phases.

Test status when this was packaged: **51 passed** (28 original + 23 schema tests) against a
throwaway PostgreSQL 16 server. The Docker Compose file and the Windows commands below have
not been run by the author of this package; confirm them on your machine.

## 2. Container, volume, schema, seed, runtime inserts: what is what

| Concept | What it is | Where it comes from |
|---|---|---|
| Container | The running PostgreSQL program | `docker compose up` |
| Persistent volume | Disk storage holding the database files; survives container restarts | Named volume in `docker-compose.yml` |
| Schema | Tables, constraints, indexes | Migration files, applied by `python -m scripts.migrate` / `init_db` |
| Seed data | The initial fictional demo records | `backend/seed.sql` (safe to re-run, never overwrites) |
| Runtime inserts | New patients, resources and proposals during operation | API endpoints (later phase), never hand-written SQL |

## 3. Changing the schema safely

1. **Never edit** an applied migration. The runner stores a checksum and refuses to continue if an applied file changed.
2. Add the next numbered file, for example `backend/migrations/003_add_something.sql`. Write changes as `ALTER TABLE ...` (migrations are applied once, in order, each in its own transaction).
3. Back up with `pg_dump`, run `python -m scripts.init_db`, then `pytest`.
4. For a deliberate wipe of demo data (structure kept): `python -m scripts.reset_demo` (shows counts, requires typing `RESET`).

"""Human approval and the safe commit.

Chosen technique: a CONDITIONAL UPDATE inside a transaction (plus a row lock on the
proposal). In plain English:

  - A transaction is an all-or-nothing group of database steps.
  - The nurse UPDATE has a WHERE clause: "only if still available AND still at the
    version the proposal was validated against". If someone else changed the nurse
    first, the UPDATE changes 0 rows and we know the proposal is stale.
  - If two approvals race, PostgreSQL makes the second UPDATE wait for the first to
    finish, then re-checks the WHERE clause against the new data, so it changes 0 rows.
  - `SELECT ... FOR UPDATE` on the proposal makes a double-click on the SAME proposal
    queue up, and the second attempt sees the status is no longer 'pending_review'.
"""

from backend import database
from backend.hospital_state import is_state_current
from backend.schemas import ApprovalResult


def _rejected(proposal_id: str, reason: str, nurse_id=None) -> ApprovalResult:
    return ApprovalResult(proposal_id=proposal_id, outcome="rejected", reason=reason, nurse_id=nurse_id)


def approve_proposal(conn, proposal_id: str, reviewer: str, reason: str = "") -> ApprovalResult:
    """Reviewer approves. Returns outcome 'committed', 'rejected' or 'stale'.

    If any database step raises an error, the whole transaction rolls back and the
    exception is re-raised: nothing is half-applied.
    """
    if not reviewer.strip():
        raise ValueError("Reviewer name is required.")

    with conn.transaction():
        proposal = database.get_proposal(conn, proposal_id, for_update=True)
        if proposal is None:
            return _rejected(proposal_id, "Proposal not found.")

        nurse_id = proposal["proposed_nurse_id"]

        # Only a proposal still waiting for review can be decided; this blocks repeats.
        if proposal["status"] != "pending_review":
            database.add_audit_event(conn, "approval_blocked", proposal_id, {
                "reviewer": reviewer, "reason": f"status is {proposal['status']}"})
            return _rejected(
                proposal_id,
                f"Proposal cannot be approved: status is {proposal['status']}.",
                nurse_id,
            )

        # Defence in depth: an invalid proposal can never be approved by a click.
        saved_version = proposal["state_version_used"]
        if not proposal["validation_valid"] or saved_version is None:
            database.add_audit_event(conn, "approval_blocked", proposal_id, {
                "reviewer": reviewer, "reason": "proposal did not pass validation"})
            return _rejected(proposal_id, "Proposal did not pass validation.", nurse_id)

        # The safe commit: change the nurse only if nothing has changed since validation.
        new_version = database.mark_nurse_assigned(conn, nurse_id, saved_version)

        if new_version is None:
            nurse = database.get_nurse(conn, nurse_id)
            current_version = nurse["state_version"] if nurse else None
            if nurse is None:
                why = f"Nurse {nurse_id} no longer exists."
            elif not is_state_current(saved_version, current_version):
                why = (f"State changed since validation "
                       f"(validated at version {saved_version}, now version {current_version}).")
            else:
                why = f"Nurse {nurse_id} is no longer available."
            database.set_proposal_status(conn, proposal_id, "stale")
            database.add_audit_event(conn, "approval_failed_stale", proposal_id, {
                "reviewer": reviewer, "reason": why,
                "saved_version": saved_version, "current_version": current_version})
            return ApprovalResult(
                proposal_id=proposal_id, outcome="stale", reason=why, nurse_id=nurse_id)

        # Success path: all of these are committed together, or none of them are.
        database.record_approval(conn, proposal_id, reviewer, "approved", reason)
        database.set_proposal_status(conn, proposal_id, "approved")
        database.add_audit_event(conn, "reviewer_approved", proposal_id, {
            "reviewer": reviewer, "reason": reason})
        database.add_audit_event(conn, "assignment_committed", proposal_id, {
            "nurse_id": nurse_id, "new_state_version": new_version})
        return ApprovalResult(
            proposal_id=proposal_id,
            outcome="committed",
            reason=f"Nurse {nurse_id} assigned.",
            nurse_id=nurse_id,
            new_state_version=new_version,
        )


def reject_proposal(conn, proposal_id: str, reviewer: str, reason: str = "") -> ApprovalResult:
    """Reviewer rejects. The nurse is never changed."""
    if not reviewer.strip():
        raise ValueError("Reviewer name is required.")

    with conn.transaction():
        proposal = database.get_proposal(conn, proposal_id, for_update=True)
        if proposal is None:
            return _rejected(proposal_id, "Proposal not found.")

        nurse_id = proposal["proposed_nurse_id"]
        if proposal["status"] != "pending_review":
            database.add_audit_event(conn, "rejection_blocked", proposal_id, {
                "reviewer": reviewer, "reason": f"status is {proposal['status']}"})
            return _rejected(
                proposal_id,
                f"Proposal cannot be rejected: status is {proposal['status']}.",
                nurse_id,
            )

        database.record_approval(conn, proposal_id, reviewer, "rejected", reason)
        database.set_proposal_status(conn, proposal_id, "rejected_by_reviewer")
        database.add_audit_event(conn, "reviewer_rejected", proposal_id, {
            "reviewer": reviewer, "reason": reason})
        return _rejected(proposal_id, "Rejected by reviewer.", nurse_id)

"""Database access layer (PostgreSQL via psycopg 3).

Conventions used everywhere in this file:
- Every function takes `conn` (an open connection) as its first argument, so
  several calls can share ONE transaction.
- Connections are opened with autocommit=True. A multi-step change is wrapped in
  `with conn.transaction():` (see approval.py), which is an explicit
  BEGIN ... COMMIT block that rolls back automatically if an error happens.
- SQL uses %s placeholders and passes values separately. Values are never pasted
  into the SQL text, which prevents SQL injection.
- Rows come back as dictionaries (dict_row), e.g. nurse["available"].
"""

import os
from typing import Optional

import psycopg
from dotenv import load_dotenv
from psycopg.rows import dict_row
from psycopg.types.json import Jsonb

load_dotenv()  # reads the .env file in the project folder, if present


def get_connection(database_url: Optional[str] = None) -> psycopg.Connection:
    """Open a connection. Use it as: `with get_connection() as conn: ...`
    (the `with` block closes the connection for you)."""
    url = database_url or os.environ.get("DATABASE_URL")
    if not url:
        raise RuntimeError("DATABASE_URL is not set. Copy .env.example to .env and edit it.")
    return psycopg.connect(url, autocommit=True, row_factory=dict_row)


# ---------------------------------------------------------------- nurses (reads)

_NURSE_COLUMNS = "nurse_id, name, available, department, state_version"


def get_nurse(conn, nurse_id: str) -> Optional[dict]:
    """Return one nurse as a dict, or None if no such nurse exists."""
    cur = conn.execute(
        f"SELECT {_NURSE_COLUMNS} FROM nurses WHERE nurse_id = %s", (nurse_id,)
    )
    return cur.fetchone()


def list_nurses(conn) -> list[dict]:
    cur = conn.execute(f"SELECT {_NURSE_COLUMNS} FROM nurses ORDER BY nurse_id")
    return cur.fetchall()


def list_available_nurses(conn) -> list[dict]:
    cur = conn.execute(
        f"SELECT {_NURSE_COLUMNS} FROM nurses WHERE available = TRUE ORDER BY nurse_id"
    )
    return cur.fetchall()


def get_state_version(conn, nurse_id: str) -> Optional[int]:
    """Current state version of one nurse, or None if the nurse does not exist."""
    cur = conn.execute("SELECT state_version FROM nurses WHERE nurse_id = %s", (nurse_id,))
    row = cur.fetchone()
    return row["state_version"] if row else None


# ------------------------------------------------------------ nurses (the one write)

def mark_nurse_assigned(conn, nurse_id: str, expected_version: int) -> Optional[int]:
    """Conditionally mark a nurse unavailable.

    The UPDATE only changes the row if the nurse is STILL available AND still at
    the version the proposal was validated against. Check and change happen in a
    single statement, so two people cannot both succeed.

    Returns the new state version if the row was changed, or None if it was not
    (meaning the proposal is stale).
    """
    cur = conn.execute(
        """
        UPDATE nurses
           SET available = FALSE,
               state_version = state_version + 1
         WHERE nurse_id = %s
           AND available = TRUE
           AND state_version = %s
        RETURNING state_version
        """,
        (nurse_id, expected_version),
    )
    row = cur.fetchone()
    return row["state_version"] if row else None


# ---------------------------------------------------------------------- proposals

_PROPOSAL_COLUMNS = (
    "proposal_id, incident_description, proposed_nurse_id, validation_valid, "
    "validation_reason, state_version_used, status, created_at"
)


def save_proposal(
    conn,
    *,
    proposal_id: str,
    incident_description: str,
    proposed_nurse_id: str,
    valid: bool,
    reason: str,
    state_version_used: Optional[int],
    status: str,
) -> None:
    conn.execute(
        """
        INSERT INTO proposals
            (proposal_id, incident_description, proposed_nurse_id,
             validation_valid, validation_reason, state_version_used, status)
        VALUES (%s, %s, %s, %s, %s, %s, %s)
        """,
        (proposal_id, incident_description, proposed_nurse_id,
         valid, reason, state_version_used, status),
    )


def get_proposal(conn, proposal_id: str, for_update: bool = False) -> Optional[dict]:
    """Return one proposal, or None.

    for_update=True adds `FOR UPDATE`, which LOCKS the row until the surrounding
    transaction ends. Other transactions that try to lock the same proposal wait.
    """
    sql = f"SELECT {_PROPOSAL_COLUMNS} FROM proposals WHERE proposal_id = %s"
    if for_update:
        sql += " FOR UPDATE"
    return conn.execute(sql, (proposal_id,)).fetchone()


def set_proposal_status(conn, proposal_id: str, status: str) -> None:
    conn.execute(
        "UPDATE proposals SET status = %s WHERE proposal_id = %s", (status, proposal_id)
    )


# ---------------------------------------------------------------------- approvals

def record_approval(conn, proposal_id: str, reviewer: str, decision: str, reason: str) -> int:
    """Store the reviewer's decision ('approved' or 'rejected'). Returns approval_id."""
    cur = conn.execute(
        """
        INSERT INTO approvals (proposal_id, reviewer, decision, reason)
        VALUES (%s, %s, %s, %s)
        RETURNING approval_id
        """,
        (proposal_id, reviewer, decision, reason),
    )
    return cur.fetchone()["approval_id"]


def list_approvals(conn, proposal_id: Optional[str] = None) -> list[dict]:
    if proposal_id is None:
        cur = conn.execute("SELECT * FROM approvals ORDER BY approval_id")
    else:
        cur = conn.execute(
            "SELECT * FROM approvals WHERE proposal_id = %s ORDER BY approval_id",
            (proposal_id,),
        )
    return cur.fetchall()


# -------------------------------------------------------------------- audit trail

def add_audit_event(conn, action: str, proposal_id: Optional[str], details: dict) -> None:
    """Append one audit event. `details` must be plain, non-sensitive data
    (never API keys or secrets). Jsonb() tells psycopg to store the dict as JSON."""
    conn.execute(
        "INSERT INTO audit_logs (proposal_id, action, details) VALUES (%s, %s, %s)",
        (proposal_id, action, Jsonb(details)),
    )


def list_audit_events(conn, proposal_id: Optional[str] = None) -> list[dict]:
    """All events in order, or only the events for one proposal."""
    if proposal_id is None:
        cur = conn.execute("SELECT * FROM audit_logs ORDER BY event_id")
    else:
        cur = conn.execute(
            "SELECT * FROM audit_logs WHERE proposal_id = %s ORDER BY event_id",
            (proposal_id,),
        )
    return cur.fetchall()

"""Seeded evaluation scenarios for the validator.

Runs entirely in memory against the three fictional seed nurses, so results are the
same every time and no database is touched. Run it with:

    python -m backend.evaluation

This checks the prototype's rules on fictional data. It is NOT a clinical validation.
"""

import sys

from backend.schemas import ProposalInput
from backend.validator import validate_against_record

# Must match backend/seed.sql (tests/test_scenarios.py checks that they agree).
SEED_NURSES = {
    "N01": {"nurse_id": "N01", "name": "Person A", "available": True,  "department": "Emergency", "state_version": 1},
    "N02": {"nurse_id": "N02", "name": "Person B", "available": False, "department": "ICU",       "state_version": 1},
    "N03": {"nurse_id": "N03", "name": "Person C", "available": True,  "department": "Emergency", "state_version": 1},
}

INCIDENT = "Fictional incident: simulated emergency in bay 2."

SCENARIOS = [
    {"name": "Available Person A",       "nurse_id": "N01", "expect_valid": True,  "expect_text": "exists and is available"},
    {"name": "Unavailable Person B",     "nurse_id": "N02", "expect_valid": False, "expect_text": "currently unavailable"},
    {"name": "Available Person C",       "nurse_id": "N03", "expect_valid": True,  "expect_text": "exists and is available"},
    {"name": "Nonexistent nurse N99",    "nurse_id": "N99", "expect_valid": False, "expect_text": "does not exist"},
    {"name": "Wrong case (n01)",         "nurse_id": "n01", "expect_valid": False, "expect_text": "does not exist"},
    {"name": "Blank nurse ID",           "nurse_id": "  ",  "expect_valid": False, "expect_text": "empty"},
]


def run_scenarios() -> list[dict]:
    """Run every scenario and return one result dict per scenario."""
    results = []
    for number, scenario in enumerate(SCENARIOS, start=1):
        proposal = ProposalInput(
            proposal_id=f"EVAL-{number}",
            incident_description=INCIDENT,
            proposed_nurse_id=scenario["nurse_id"],
        )
        outcome = validate_against_record(proposal, SEED_NURSES.get(scenario["nurse_id"]))
        passed = (outcome.valid == scenario["expect_valid"]
                  and scenario["expect_text"] in outcome.reason)
        results.append({"name": scenario["name"], "passed": passed,
                        "valid": outcome.valid, "reason": outcome.reason})
    return results


def main() -> int:
    results = run_scenarios()
    for r in results:
        print(f"[{'PASS' if r['passed'] else 'FAIL'}] {r['name']}: valid={r['valid']} - {r['reason']}")
    failed = sum(1 for r in results if not r["passed"])
    print(f"\n{len(results) - failed}/{len(results)} scenarios passed.")
    return 1 if failed else 0


if __name__ == "__main__":
    sys.exit(main())

"""Resource state: how the rest of the backend reads "what is true right now".

The database is the source of truth. Nothing here caches data in Python.

How state versions work:
  - Every nurse row has a state_version, starting at 1.
  - Each time the row changes (a nurse is assigned), the version goes up by 1.
  - A proposal remembers the version it was validated against.
  - If the nurse's current version differs from the remembered one, something
    changed in between, so the proposal is STALE and must not be committed.
"""

from typing import Optional

from backend import database


def get_nurse_state(conn, nurse_id: str) -> Optional[dict]:
    return database.get_nurse(conn, nurse_id)


def get_all_nurse_states(conn) -> list[dict]:
    return database.list_nurses(conn)


def get_available_nurse_states(conn) -> list[dict]:
    return database.list_available_nurses(conn)


def get_state_version(conn, nurse_id: str) -> Optional[int]:
    return database.get_state_version(conn, nurse_id)


def is_state_current(saved_version: Optional[int], current_version: Optional[int]) -> bool:
    """True only if both versions exist and are equal. A pure function: no database."""
    return saved_version is not None and saved_version == current_version

from pydantic import BaseModel, Field


class ProposalInput(BaseModel):
    """What Person A's AI code sends us. It does NOT include a state version:
    any extra field such as "state_version" is ignored, because the backend
    reads the real version from the database itself."""

    proposal_id: str = Field(min_length=1)
    incident_description: str
    proposed_nurse_id: str


class ValidationResult(BaseModel):
    valid: bool
    reason: str
    nurse_id: str                       # the nurse ID the AI proposed, exactly as received
    state_version: Optional[int] = None  # None when the nurse does not exist


class ApprovalResult(BaseModel):
    proposal_id: str
    outcome: Literal["committed", "rejected", "stale"]
    reason: str
    nurse_id: Optional[str] = None
    new_state_version: Optional[int] = None  # only set when outcome == "committed"

"""Deterministic validator: plain Python rules, no AI involved.

Two layers:
  1. validate_against_record(proposal, nurse)  - PURE: no database, easy to unit test.
  2. validate_proposal / validate_and_save_proposal - read the database, then call (1).
"""

from typing import Optional

from backend import database, hospital_state
from backend.schemas import ProposalInput, ValidationResult


def validate_against_record(proposal: ProposalInput, nurse: Optional[dict]) -> ValidationResult:
    """Decide whether a proposal is valid, given the nurse record (or None if no such nurse)."""
    nurse_id = proposal.proposed_nurse_id

    # Basic assignment rules (the only ones agreed so far; add more only after the team agrees).
    if not nurse_id.strip():
        return ValidationResult(valid=False, reason="Proposed nurse ID is empty.", nurse_id=nurse_id)
    if not proposal.incident_description.strip():
        return ValidationResult(valid=False, reason="Incident description is empty.", nurse_id=nurse_id)

    # A nonexistent nurse and an unavailable nurse are different problems.
    if nurse is None:
        return ValidationResult(valid=False, reason=f"Nurse {nurse_id} does not exist.", nurse_id=nurse_id)

    if not nurse["available"]:
        return ValidationResult(
            valid=False,
            reason=f"Nurse {nurse_id} exists but is currently unavailable.",
            nurse_id=nurse_id,
            state_version=nurse["state_version"],
        )

    return ValidationResult(
        valid=True,
        reason=f"Nurse {nurse_id} exists and is available.",
        nurse_id=nurse_id,
        state_version=nurse["state_version"],
    )


def validate_proposal(conn, proposal: ProposalInput) -> ValidationResult:
    """Read the nurse from the database (the authority) and validate. Saves nothing."""
    nurse = hospital_state.get_nurse_state(conn, proposal.proposed_nurse_id)
    return validate_against_record(proposal, nurse)


def validate_and_save_proposal(conn, proposal: ProposalInput) -> ValidationResult:
    """Validate, then store the proposal, its result and audit events in ONE transaction.

    Invalid proposals are stored too (status 'rejected_by_validator') so the AI's
    mistakes stay visible for auditing.
    """
    if database.get_proposal(conn, proposal.proposal_id) is not None:
        raise ValueError(f"Proposal {proposal.proposal_id} already exists.")

    result = validate_proposal(conn, proposal)
    status = "pending_review" if result.valid else "rejected_by_validator"

    with conn.transaction():
        database.save_proposal(
            conn,
            proposal_id=proposal.proposal_id,
            incident_description=proposal.incident_description,
            proposed_nurse_id=proposal.proposed_nurse_id,
            valid=result.valid,
            reason=result.reason,
            state_version_used=result.state_version if result.valid else None,
            status=status,
        )
        database.add_audit_event(
            conn, "proposal_created", proposal.proposal_id,
            {"nurse_id": proposal.proposed_nurse_id},
        )
        database.add_audit_event(
            conn,
            "validation_passed" if result.valid else "validation_failed",
            proposal.proposal_id,
            {"reason": result.reason, "nurse_id": result.nurse_id,
             "state_version": result.state_version},
        )
    return result

-- and the existing nurse-only workflow and its tests keep working.
--
-- Design rules used throughout:
--   * Every resource row that can be reserved has a state_version (optimistic concurrency).
--   * "Belongs to the correct hospital" is enforced by the database through composite
--     foreign keys (resource_id, hospital_id), not only by Python.
--   * AI-supplied IDs (proposal_items.resource_id) have NO foreign key, so invalid
--     AI suggestions can still be stored and audited.

--     the database itself refuses two active allocations of the same bed.

-- Trigger: a ward cannot hold more beds than its capacity, and a bed's type must
-- match its ward's type. Locking the ward row serialises two simultaneous bed inserts.
CREATE FUNCTION enforce_ward_rules() RETURNS trigger AS $$
DECLARE
    ward_capacity INTEGER;
    ward_kind     TEXT;
    bed_count     INTEGER;
BEGIN
    SELECT capacity, ward_type INTO ward_capacity, ward_kind
      FROM wards WHERE ward_id = NEW.ward_id FOR UPDATE;

    IF ward_kind <> NEW.bed_type THEN
        RAISE EXCEPTION 'Bed type % does not match ward type % for ward %',
            NEW.bed_type, ward_kind, NEW.ward_id;
    END IF;

    SELECT count(*) INTO bed_count FROM beds
     WHERE ward_id = NEW.ward_id AND bed_id <> NEW.bed_id;
    IF bed_count >= ward_capacity THEN
        RAISE EXCEPTION 'Ward % is at capacity (%)', NEW.ward_id, ward_capacity;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER beds_enforce_ward_rules
    BEFORE INSERT OR UPDATE OF ward_id, bed_type ON beds
    FOR EACH ROW EXECUTE FUNCTION enforce_ward_rules();

# Entity relationship design (Phase 2)

Fictional data only. Not clinically validated.

## Diagram

```mermaid
    proposals |o--o{ audit_logs : "history"
```

`policy_settings` (configurable validator limits) and `schema_migrations` (migration
bookkeeping) stand alone.

## How the tables relate

| Table | Purpose | Key relationships |
|---|---|---|
| `hospitals` | Identity, location, status, `max_concurrent_patients` cap | Parent of almost everything |
| `wards` | Ward type, capacity, open/closed | Belongs to a hospital |
| `nurses`, `doctors` | Staff, shift, availability, `state_version` | Belong to a hospital |
| `beds` | Bed type and status (`free`, `reserved`, `occupied`, `cleaning`, `out_of_service`) plus version | Belong to a ward **and** the same hospital |
| `equipment_types`, `equipment_units` | Each physical unit tracked individually (status, maintenance date, version) | Unit belongs to a hospital; optional ward in that hospital |
| `patients` | Fictional patients (the database refuses `is_fictional = FALSE`) | Linked to incidents |
| `incidents`, `incident_patients` | Emergency, reported severity, arrival time, status, Agent A extraction (JSONB) | Incident belongs to the receiving hospital; many patients per incident |
| `proposals` | AI plans: input snapshot, validation errors/warnings, unmet requirements, explanation, alternatives (`parent_proposal_id`, `plan_label`) | Bundle proposals point to an incident and patient |
| `proposal_items` | One row per resource the AI proposed | `resource_id` has **no** foreign key, so invalid AI suggestions stay auditable |
| `approvals` | Reviewer decision: approved, rejected, or revision requested | One decision per proposal; optional link to `app_users` |
| `allocations` | The complete committed bundle for one patient of one incident | Created from exactly one proposal |
| `allocation_items` | The bed, doctor(s), nurse(s), equipment unit(s) in the bundle | Each item references exactly one resource in the same hospital |
| `audit_logs` | Append-only history with actor and entity | Optional link to a proposal |
| `app_users` | Administrators and reviewers (hash column filled in the auth phase) | Referenced by approvals |
| `policy_settings` | Workload limits and demo policy placeholders read by the validator | None |

## Rules the database enforces by itself

| Rule | Mechanism |
|---|---|
| A resource belongs to the same hospital as its ward / allocation | Composite foreign keys `(id, hospital_id)` |
| A patient can only be allocated under an incident they belong to | Composite FK to `incident_patients` |
| A bed or equipment unit has at most one **active** allocation | Partial unique indexes (`WHERE status = 'active'`) |
| A patient has at most one active allocation; an allocation has at most one active bed | Partial unique indexes |
| An allocation item fills exactly the column matching its `resource_type` | CHECK `exactly_one_resource` |
| Active allocations have no end time; ended ones do | CHECK `active_means_not_ended` |
| A ward holds no more beds than its capacity; bed type matches ward type | Trigger `enforce_ward_rules` |
| Only fictional patients can be stored | CHECK `patients_must_be_fictional` |
| An invalid proposal can only ever have status `rejected_by_validator` | CHECK `status_matches_validation` (from migration 001) |
| Each proposal is decided at most once | `UNIQUE (proposal_id)` on approvals |
| Audit rows cannot be edited or deleted | Trigger `audit_logs_are_append_only` |

## Design decisions to know about

- **Per-row versions.** Beds, doctors, nurses and equipment units each carry a `state_version`, increased on every change. A proposal item remembers the version the *backend* read.
- **Cleaning is part of bed `status`.** A separate cleaning column could contradict the status, so `'cleaning'` is one of its values.
- **Doctors and nurses may serve several patients.** Their limit comes from `policy_settings`, not a unique index. Beds and equipment units are exclusive.
- **Workload is derived, not stored.** Active patients per staff member are counted from active `allocation_items`, avoiding a duplicate counter that could drift.
- **Not yet enforced by the database (Phase 5-6, Python):** hospital capacity vs `max_concurrent_patients`, workload limits, ICU eligibility policy, shift matching, and "required components present". Reasons: they depend on configurable policy or on counting across rows.
- **`TRUNCATE` bypasses the audit-log trigger.** Real protection will also need a restricted database role for the API (later phase); test and demo-reset tooling deliberately truncate.

"""Small helpers shared by the init script, the reset script and the tests."""

from pathlib import Path

from psycopg import sql

SEED_FILE = Path(__file__).resolve().parent.parent / "backend" / "seed.sql"


def apply_seed(conn) -> None:
    """Insert the fictional demo data. Safe to repeat: existing rows are never overwritten."""
    conn.execute(SEED_FILE.read_text(encoding="utf-8"))


def application_tables(conn) -> list[str]:
    """Names of all application tables (everything except the migration bookkeeping table)."""
    rows = conn.execute(
        """
        SELECT table_name FROM information_schema.tables
         WHERE table_schema = 'public' AND table_type = 'BASE TABLE'
           AND table_name <> 'schema_migrations'
         ORDER BY table_name
        """
    ).fetchall()
    return [r["table_name"] for r in rows]


def row_counts(conn) -> dict[str, int]:
    counts = {}
    for name in application_tables(conn):
        query = sql.SQL("SELECT count(*) AS n FROM {}").format(sql.Identifier(name))
        counts[name] = conn.execute(query).fetchone()["n"]
    return counts


def truncate_all_tables(conn) -> None:
    """DESTRUCTIVE: empties every application table. Only for tests and the reset script.
    Table names come from the database itself and are quoted with sql.Identifier."""
    names = application_tables(conn)
    if names:
        query = sql.SQL("TRUNCATE {} RESTART IDENTITY CASCADE").format(
            sql.SQL(", ").join(sql.Identifier(n) for n in names)
        )
        conn.execute(query)

"""Apply pending database migrations.

A migration is a numbered .sql file in backend/migrations/. This script:
  1. creates a bookkeeping table, schema_migrations, if needed;
  2. applies every file that has not been applied yet, in filename order,
     each inside its own transaction (all-or-nothing);
  3. records each applied file with a checksum.

If a file that was already applied has since been edited, it stops with an error:
applied migrations must never change. Add a new numbered file instead.

Run from the project folder:  python -m scripts.migrate
"""

import hashlib
from pathlib import Path

from backend.database import get_connection

MIGRATIONS_DIR = Path(__file__).resolve().parent.parent / "backend" / "migrations"
LOCK_ID = 7234001   # any fixed number; stops two migrators running at the same time


def migration_files() -> list[Path]:
    return sorted(MIGRATIONS_DIR.glob("*.sql"))


def checksum_of(path: Path) -> str:
    # read_text normalises Windows (CRLF) line endings, so the checksum is the same on every machine.
    return hashlib.sha256(path.read_text(encoding="utf-8").encode("utf-8")).hexdigest()


def apply_migrations(conn) -> list[str]:
    """Apply all pending migrations. Returns the names of the ones applied now."""
    conn.execute("SELECT pg_advisory_lock(%s)", (LOCK_ID,))
    try:
        conn.execute(
            """
            CREATE TABLE IF NOT EXISTS schema_migrations (
                version    TEXT PRIMARY KEY,
                checksum   TEXT NOT NULL,
                applied_at TIMESTAMPTZ NOT NULL DEFAULT now()
            )
            """
        )
        done = {r["version"]: r["checksum"]
                for r in conn.execute("SELECT version, checksum FROM schema_migrations").fetchall()}

        applied_now = []
        for path in migration_files():
            digest = checksum_of(path)
            if path.name in done:
                if done[path.name] != digest:
                    raise RuntimeError(
                        f"Migration {path.name} was edited after it was applied. "
                        "Restore the original file and add a new migration instead."
                    )
                continue
            with conn.transaction():
                conn.execute(path.read_text(encoding="utf-8"))
                conn.execute(
                    "INSERT INTO schema_migrations (version, checksum) VALUES (%s, %s)",
                    (path.name, digest),
                )
            applied_now.append(path.name)
        return applied_now
    finally:
        conn.execute("SELECT pg_advisory_unlock(%s)", (LOCK_ID,))


def main() -> None:
    with get_connection() as conn:
        applied = apply_migrations(conn)
        if applied:
            for name in applied:
                print(f"Applied {name}")
        else:
            print("Database is up to date. Nothing to apply.")


if __name__ == "__main__":
    main()

def _run_together(test_db_url, calls):
    """Run each (proposal_id, reviewer) approval in its own thread and connection,
    starting at the same moment. Returns the list of outcomes."""
    outcomes = []
    barrier = threading.Barrier(len(calls))

    def worker(proposal_id, reviewer):
        with database.get_connection(test_db_url) as c:
            barrier.wait()
            outcomes.append(approval.approve_proposal(c, proposal_id, reviewer).outcome)

    threads = [threading.Thread(target=worker, args=call) for call in calls]
    for t in threads:
        t.start()
    for t in threads:
        t.join(timeout=30)
    return outcomes


def test_simultaneous_approvals_for_same_nurse_only_one_commits(conn, test_db_url):
    validate_and_save_proposal(conn, make_proposal("PA", "N01"))
    validate_and_save_proposal(conn, make_proposal("PB", "N01"))

    outcomes = _run_together(test_db_url, [("PA", "Reviewer 1"), ("PB", "Reviewer 2")])

    assert sorted(outcomes) == ["committed", "stale"]
    assert database.get_nurse(conn, "N01")["state_version"] == 2
    assert len(database.list_approvals(conn)) == 1

    assert sorted(outcomes) == ["committed", "rejected"]
    assert database.get_nurse(conn, "N01")["state_version"] == 2
    assert len(database.list_approvals(conn, "PA")) == 1


def test_database_failure_rolls_back_everything(conn, monkeypatch):
    validate_and_save_proposal(conn, make_proposal("P7", "N01"))
    real_add_audit_event = database.add_audit_event

    def failing_add_audit_event(c, action, proposal_id, details):
        if action == "assignment_committed":      # fail at the very last step
            raise RuntimeError("simulated database failure")

    actions = [e["action"] for e in database.list_audit_events(conn, "P7")]
    assert "assignment_committed" not in actions and "reviewer_approved" not in actions

    name = "002_hospital_wide.sql"
    real = migrate.checksum_of(migrate.MIGRATIONS_DIR / name)
